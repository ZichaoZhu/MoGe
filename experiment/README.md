# MoGe-3 实验归档

原有 Exp1–26 已按研究问题合并为四个阶段。顶层只展示阶段结论；每次运行的原始
配置、指标、日志和可视化仍保存在对应阶段的 `runs/` 中，以便追溯。

## 阶段总览

| 阶段 | 原实验 | 核心问题 | 结论 |
|---|---|---|---|
| [阶段一：学习能力验证](stage1_learning_capability/README.md) | Exp1–5 | SSR 能否学习，以及只训练 SSR 是否能够泛化 | 能过拟合训练样本，但小数据下独立场景普遍退化 |
| [阶段二：训练策略验证](stage2_training_strategy/README.md) | Exp6–15 | Base/2D Head、SSR、分离训练和联合训练应如何组合 | 更新二维模块是必要的；当前收益常主要来自 K=0，尚未复现 SSR 泛化优势 |
| [阶段三：稳定性与归一化诊断](stage3_stability_normalization/README.md) | Exp16–24 | SSR 残差为何漂移并导致体素跨度和显存异常 | 主要定位到 SSR BatchNorm 运行统计失配和递归放大；更大 microbatch 只能缓解 |
| [阶段四：损失与梯度诊断](stage4_loss_gradient_audit/README.md) | Exp25–26 | 为什么细结构训练收益难以迁移到留出数据 | 边缘监督在参数空间较弱，梯度高度集中于输出层，且不同数据划分存在方向冲突 |

四个阶段形成以下证据链：

1. 先证明实现具备学习能力，并区分训练拟合和泛化；
2. 再用 K=0 与 K≥1 拆分二维模块和 SSR 的贡献；
3. 对联合训练后出现的残差坍塌进行析因；
4. 最后审计监督信号为何没有稳定转化为跨域细结构收益。

因此，现有实验支持“论文式协同训练路线比固定 Base 更合理”，但不能表述为已经
完整复现论文效果。当前实现仍存在小数据过拟合、SSR 推理统计依赖和留出集退化。

## 目录约定

```text
experiment/
├── stage1_learning_capability/
├── stage2_training_strategy/
├── stage3_stability_normalization/
├── stage4_loss_gradient_audit/
└── EXPERIMENT_TEMPLATE.md
```

每个阶段目录包含：

- `README.md`：阶段假设、证据链、主要结果和边界；
- `runs/expN_*/`：原实验的完整归档，不重新编号；
- 原实验内部的配置、指标和轻量产物。

大型检查点和受许可证约束的数据仍保存在训练服务器。历史报告中的服务器绝对路径
表示实验运行时的真实位置；目录重组不会伪造这些路径，也不会自动搬迁服务器文件。
未来重新运行时，启动脚本使用当前阶段化目录。

## Git 记录原则

从本次整理开始，Git 以“研究阶段”而不是“每个短诊断实验”为提交单位。阶段内仍
可进行多次运行，但结果在阶段完成或形成稳定结论后统一提交。提交正文应记录：

- 包含的原实验编号；
- 关键指标和失败结果；
- 能够证明与不能证明的结论；
- 大型产物的服务器位置和校验和。

未实际运行的方案不得登记为已完成实验。
