# Exp19：SSR BatchNorm 运行统计重校准

## 实验问题

Exp18 已在保持权重完全不变的四组合扫描中证明：六张残差离群图只在 SSR
处于 eval 模式时出现，Base 的 train/eval 状态不改变异常身份。当前 SSR 内部
唯一依赖 train/eval 状态的模块是 `BatchNorm1d`。

本实验不训练、不更新任何可学习参数，也不改动 Exp15 原始检查点。仅使用 100 张
训练图重新估计 SSR BatchNorm 的 running mean/variance，然后统一在 eval 模式
下检查：

1. 六张离群图和 K=3 最大残差是否消失；
2. K=0/1/3/5 的 train/val/test 全图与结构指标是否改善或至少不退化；
3. 真正的 SSR 校准 batch 1 与 batch 8 是否存在差异。

如果重校准能显著修复推理残差，就证明 Exp15/16 的一部分问题来自部署统计，而非
权重本身完全没有学习能力。若仍无效，再考虑替换归一化或重新训练。

## 固定设计

- 起点：Exp15 step 800，SHA-256
  `f602855f9e5628e27393734f121a5ffa2f485e1cbfd1c410a2ed0850ca5200fa`；
- 校准数据：原有 100 张 Hypersim 训练图，固定顺序、无增强；
- 图像：384×512，`num_tokens=2500`，K=3；
- 两个实验臂：真实 SSR 校准 batch 1 与 batch 8；
- Base 始终 eval；SSR 临时 train，仅让 BatchNorm 更新运行缓冲；
- 每个实验臂先把 running mean/variance 重置为 0/1，使用
  `momentum=None` 做累计平均；
- 校准完成后恢复 BatchNorm 原始 momentum，再切回 eval；
- 检查所有模型状态，除 SSR 的 running mean、running variance 和
  `num_batches_tracked` 外必须逐元素不变；
- 校准检查点只保存在服务器，原始检查点保持未修改。

## 运行结果

8 张图冒烟测试先验证了 batch 8 可行：峰值显存 6.68 GiB，随后才启动正式实验。
正式实验于 2026-08-02 08:28:51–08:35:03 在物理 GPU 1 上完成，用时
6 分 12 秒。监督程序在 08:28:50 和 08:38:50 检查，实际间隔
600.065 秒并确认任务正常完成。两个实验臂均通过状态审计：

- 108 个 SSR BatchNorm 缓冲区发生预期变化；
- 其余 609 个模型状态逐元素完全不变；
- K=0 的 train/val/test Point Rel 与原检查点最大绝对差为 0；
- 原始检查点未修改，两个重校准检查点另存于服务器。

batch 1 和 batch 8 校准峰值显存分别为 2.28 GiB 和 7.53 GiB。每个
BatchNorm 在原检查点中记录了 `19200=800×8×3` 次更新，直接证实所谓
global batch 8 实际是 8 次 microbatch 1 前向和 3 次共享 SSR 调用，BN 从未
在一次前向中观察到 8 张图。

### 重校准能缓解、但不能消除残差离群

| 运行统计 | eval 最大 \(|\Delta\log Z|\) | 相对下降 | 越界图数 |
|---|---:|---:|---:|
| 原始检查点 | 1.0458 | — | 6/132 |
| 100 张重校准，batch 1 | 0.9446 | 9.68% | 3/132 |
| 100 张重校准，batch 8 | **0.8124** | **22.32%** | **2/132** |

batch 8 优于 batch 1，证明更丰富的真实前向批统计确实更接近部署分布；但两者
都没有越过 0.5 安全目标。batch 8 剩余两张离群图为
`ai_027_005_cam_00_frame.0000` 和
`ai_045_004_cam_01_frame.0099`，最坏值仍发生在 K=3。K=1 和 K=2 的
全量最大值分别只有 0.3493 和 0.4752，说明主要问题仍是第三轮递归放大。

### 几何指标小幅改善

下表为 K=3 Point Rel；括号是相对原始检查点的变化，正数表示误差下降。

| 范围 | 原始 | 重校准 batch 1 | 重校准 batch 8 |
|---|---:|---:|---:|
| Train 全图 | 4.5208% | 4.4541%（+1.48%） | **4.4430%（+1.72%）** |
| Train 结构 | 5.1243% | 5.0800%（+0.87%） | **5.0732%（+1.00%）** |
| Val 全图 | 8.9050% | 8.9207%（−0.18%） | **8.8817%（+0.26%）** |
| Val 结构 | 8.7467% | 8.6652%（+0.93%） | **8.5558%（+2.18%）** |
| Test 全图 | 6.8930% | **6.8598%（+0.48%）** | 6.8693%（+0.34%） |
| Test 结构 | 9.3324% | 9.3584%（−0.28%） | **9.2759%（+0.61%）** |

batch 8 在六个范围均改善 K=3，且 K=5 改善更明显：相对原始检查点的
train/val/test 全图改善 `4.73% / 1.12% / 1.46%`，结构改善
`4.70% / 3.01% / 1.65%`。这与“运行统计失配会随递归次数放大”的判断一致。
不过绝对收益仍小，且两张严重离群图未消失，不能把重校准当成最终修复。

## 原因分析

Exp18 与 Exp19 合起来区分了两件事：

1. **BN 运行统计失配是真实原因。** 不改任何权重，仅重估统计便同时降低残差峰值、
   改善 K=3/K=5 指标；真实 batch 8 又优于 batch 1。
2. **单套运行统计不适合当前共享递归。** 同一组 BatchNorm 要依次处理 K=1、
   K=2、K=3 的不同特征分布。重校准只能把三种分布平均到一套均值/方差中，
   K=3 仍产生两张离群图；简单增加校准样本不能消除这一结构性冲突。

另外，正式 batch 8 校准前向自身曾出现最大训练态残差 0.5234，而 batch 1
最大为 0.4644。这说明“增大真实 batch”不是无条件的稳定性保证：跨图像聚合
统计会改变归一化结果。论文没有公开稀疏残差块的归一化类型，因此当前问题首先
属于复现时选用 `BatchNorm1d` 的实现风险，不能据此判定论文方法无效。

重校准也没有改变 Exp15 的核心泛化结论：最终 K=3 相对同检查点 K=0，训练集
仍明显受益，而验证和测试仍没有一致超过 K=0。它修复的是训练/部署统计差异，
不是 100 张单域数据造成的结构过拟合。

## 结论与下一步

1. Exp19 证实当前不佳结果不是单一的“权重没学会”，BN 运行统计错误贡献明确；
2. batch 8 重校准是两个臂中较好的临时检查点，但残差最大 0.8124，仍不应恢复
   联合训练或直接作为最终部署方案；
3. 下一步保持原始权重，令 SSR 在推理时按每次前向的即时批统计归一化，而不读取
   或更新 running statistics；先用单图 batch 1 完整评测残差与 Point Rel；
4. 如果即时统计同时消除离群且不损害指标，再决定采用无运行状态的归一化，或为
   每轮递归维护独立统计；若仍失败，才需要回到权重训练与残差约束。
