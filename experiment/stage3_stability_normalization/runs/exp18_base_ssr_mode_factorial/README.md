# Exp18：Base/SSR 训练与推理模式四组合析因

## 实验问题

Exp17 发现完整模型在 train 模式最大残差为 0.4653，而 eval 模式 K=3 最坏
达到 1.0458。但完整模式切换同时影响 Base 和 SSR，尚不能把差异唯一归因于
SSR 的 BatchNorm。

本实验保持 Exp15 step 800 权重完全不变，对全部 100/16/16 张图扫描：

1. Base eval + SSR eval；
2. Base eval + SSR train；
3. Base train + SSR eval；
4. Base train + SSR train。

除全 eval 外，其余组合固定随机种子重复 3 次。每次仍记录 K=1/2/3 的逐像素
残差分布。若两种 SSR eval 组合均越界、两种 SSR train 组合均安全，即可把主要
模式失配定位到 SSR 内部，而不是 DINO/二维头的训练状态。

## 运行结果

正式扫描于 2026-08-02 08:10:42–08:14:51 在物理 GPU 1 上完成，模型计算
用时 219.9 秒。共覆盖 132 张图片、4 种模块状态和 K=1/2/3；除确定性的
全 eval 组合外，其余组合各重复 3 次，最终形成 3960 条逐轮残差记录。没有
OOM、NaN、缺失样本或检查点变化。监督程序在 08:10:42 和 08:20:42 完成
两次检查，间隔 600.066 秒，最终确认扫描正常结束。

### 异常完全跟随 SSR 状态

| Base / SSR 状态 | 样本最大残差中位数 | P95 | P99 | 全局最大 | 越界样本 |
|---|---:|---:|---:|---:|---:|
| eval / eval | 0.1826 | 0.4813 | 0.6344 | **1.0458** | **6/132** |
| train / eval | 0.1826 | 0.4813 | 0.6344 | **1.0458** | **6/132** |
| eval / train | 0.1771 | 0.3546 | 0.4453 | 0.4652 | 0/132 |
| train / train | 0.1771 | 0.3546 | 0.4203 | 0.4644 | 0/132 |

两种 SSR eval 组合的六张异常图身份完全相同。尤其是把 Base 从 eval 切换到
train、同时保持 SSR eval 后，每一轮每一张图的最大残差都逐元素一致，最大和
平均绝对差均为零。反过来，只要把 SSR 切到 train，越界便全部消失，与 Base
状态无关。

SSR train 时两个 Base 状态之间存在很小的非确定性数值差异：三次重复的样本峰值
最大差为 `0.00177 / 0.03887 / 0.03710`，但均未改变任何样本是否越界。因此
不能声称所有浮点输出都严格相同，但异常的存在、身份和数量对 Base 状态不敏感。

## 原因定位

当前 SSR 中唯一随 train/eval 状态变化的层是稀疏残差块里的
`BatchNorm1d`；SSR 没有 Dropout。因此四组合实验把 Exp17 的“完整模型模式
失配”进一步定位为 **SSR BatchNorm 的运行均值/方差与训练时即时批统计不一致**，
而不是 DINO 或二维头的模式变化。

当前训练虽称 global batch 8，但每次 SSR 前向的 microbatch 是 1；八张图只是
依次前向并累积梯度。梯度累积能近似更大的优化批次，却不能合并 BatchNorm 统计，
所以 SSR 每次训练看到的是单图稀疏特征分布，部署时却使用跨历史累计的 running
statistics。这解释了为什么：

1. 训练态批统计下最大残差仅约 0.465；
2. 推理态运行统计下同一权重会达到 1.046；
3. 误差随共享 SSR 递归应用而放大，Exp17 中最大值从 K=1 的 0.4364 增至
   K=2 的 0.6298、K=3 的 1.0458；
4. 平均 Point Rel 可以改善，但少数区域仍出现明显点云爆点，K=5 还会回退。

这首先是**当前复现实现和小批量训练条件的问题**，不能归因成 MoGe-3 方法本身
失败。论文公开了稀疏三维 U-Net 的高层结构，却没有公开残差块采用哪种归一化；
当前 `BatchNorm1d` 是复现时采用的未公开结构默认值。论文训练使用 16 张 A100、
全局 batch 96 和大规模异构数据，而当前仅使用 100 张 Hypersim、microbatch 1。
即使论文官方实现也使用 BatchNorm，它每次真实前向所覆盖的图像和体素分布也会
明显更丰富；但论文没有给出每卡前向 batch 或归一化类型，因此不能把“大 batch”
说成已经证实的唯一解释。

Exp15 的留出集结果还表明存在第二个、与 BatchNorm 不同的问题：最终 SSR 的
K=0→K=3 在训练全图/结构改善 `14.26% / 17.80%`，却在验证退化
`2.90% / 7.88%`、测试退化 `0.50% / 2.92%`。这说明 100 张单一
Hypersim 小数据上的结构修正发生了过拟合。BN 重校准能够处理部署统计失配，
但不会自动解决数据多样性不足带来的泛化问题。

Exp16 则暴露第三个问题：从本检查点开始联合训练 19 次更新后，训练态批次峰值
由基线最多 `0.464669` 放大到 `0.533100`。因此即使修正 BN 推理统计，联合阶段
仍需要更保守的残差约束和 eval-mode 周期审计，不能直接恢复长训练。

## 结论与下一步

1. 已经排除 Base 训练/推理状态是六张离群图的来源；
2. 已将推理残差越界定位到 SSR 的 BatchNorm running statistics；
3. 当前结果不好由至少三层因素叠加：BN 部署统计失配、共享 SSR 递归放大，以及
   小规模单域数据上的留出集过拟合；
4. 下一项实验保持模型权重不变，仅用训练集重校准 SSR 的 BN 运行统计，比较真实
   校准 batch 1 与 batch 8；随后统一用 eval 模式扫描残差及 K=0/1/3/5 指标；
5. 在重校准证明有效前不恢复联合训练，也不放宽 0.5 安全阈值。
