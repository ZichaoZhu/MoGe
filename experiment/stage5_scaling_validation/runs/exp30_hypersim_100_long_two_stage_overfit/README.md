# Exp30：百图长程两阶段极限过拟合

状态：阶段一长程训练与自动监控进行中。

本实验从 MoGe-2 与零初始化 SSR 重新开始，不继承 Exp29 权重。训练集固定为
Exp11 的 100 张 Hypersim 图片，验证集和测试集各 16 张，只记录泛化变化，不参与
检查点选择。

训练分为两个显式阶段：

1. Detached 共适应：K=0 监督 Base/2D Head，K=1/2/3 只向 SSR 传播；
2. 完整联合：解除 detach，使精修损失同时更新 SSR、2D Head 与 DINO。

检查点按完整训练集上的
`K=3 full Point Rel + K=3 structure Point Rel` 选择。细结构区域只由 GT
对数深度边界自动确定，不使用模型预测。

`0.1*tanh(raw/0.1)`、原始残差尾部正则、梯度跳步、体素跨度预检和自动恢复均属于
小数据复现的工程稳定保护，并非论文公开的方法组成。

服务器冒烟发现未经训练的 Base 在合法 Hypersim 场景上已有 908 的深度跨度，因此
固定 512 会在 step 0 误杀正常几何。实际预检上限取
`max(512, 当前 batch 的 K=0 基础跨度 + 122)`。其中 122 来自有界更新的最坏情况：
每轮跨度最多扩张 `2×D×0.1=40` 个 bin，K=3 共 120，再加 2 个取整余量。

实验结束后，本文件将补充训练过程、最终 train/val/test 指标、失败恢复记录、资源
报告和网站入口。

若四张卡中任一卡在基准开始时不足 28 GiB 空闲显存，则不抢占或终止其他用户进程；
四卡项记录为 `skipped_resource_unavailable`，从已完成的单卡、双卡实测结果中选择
最快配置。

## 2026-08-04 安全续跑说明

首轮训练两次从普通 `resume_checkpoint.pt` 恢复后，原始残差很快再次越过 1.5。
诊断确认普通恢复点可能位于故障邻域，它只能用于非模型故障的精确续跑，不能被视为
稳定性回退点。续跑逻辑现只允许使用跨全部尝试、完成既定里程碑保存的检查点；若尚
无里程碑，则只允许回到已知安全的初始检查点。已有三个失败分支保持不变，新分支从
step 2500 里程碑以四分之一学习率继续。

如果双卡暂时不同时满足每卡 28 GiB 空闲显存，安全续跑可以从已完成基准中选择当前
可用的最快拓扑。全局 batch 仍为 8、真实 microbatch 仍为 2，因此单卡回退只改变
梯度累积方式和运行速度，不改变每次优化使用的样本数。

第 3 个续跑分支在 step 4550 后再次触发原始残差上限。排查同时发现，训练日志采用
追加写入，而旧恢复器会在整个日志中搜索 `out of memory`；因此上午的一次外部显存
抢占记录错误地污染了下午的残差失败分类，使其被误报为模型自身 OOM。现已改为只
检查本次 launch 新增的日志区间，并在重新进入失败实验时独立分类最后一次 launch。

对稳定性失败仍坚持从已完成全量评测的里程碑回退，不使用临近故障的普通 resume。
自动恢复上限由 2 次扩展为 5 次，每次恢复将 SSR、Head、DINO 学习率同时减半；
同时为 PyTorch CUDA 分配器开启 expandable segments，以降低碎片化 OOM 风险。
当前下一分支应从 step 2500 以八分之一学习率继续。该调整属于小数据长程训练的工程
保护，所有失败分支和原始日志均保留。

本实验已建立持续监控目标，每 30 分钟检查训练步、进程存活、GPU 显存、最新评测、
残差/梯度/体素跨度告警和自动恢复状态。外部抢占型 OOM 等待满足每卡 28 GiB 后从
精确断点恢复；稳定性失败则从验证里程碑降学习率恢复。

服务器同时运行独立的 `monitor_exp30.py --daemon` 守护进程，以严格的 1800 秒间隔
写入 `artifacts/monitor/history.jsonl`。文件锁保证同一实验只有一个监控器。守护
进程只自动处理已识别的 OOM、稳定性失败和意外退出；未知错误、恢复预算耗尽或不
支持的阶段会停止并保留证据，不会终止其他用户进程或绕过安全上限。

## 2026-08-05 单点残差误杀修正

`attempt_06` 在 step 8083 因原始残差绝对最大值 1.634 超过旧阈值 1.5 而安全停止，
但该批次的 P99.9 仅为 0.211，接近应用上限的像素比例仅为 0.33%。回看前五次恢复
也呈现相同模式：绝对最大值由极少数像素拉高，而残差主体分布、训练指标、梯度和
体素结构保持正常。旧规则因此把孤立 raw logit 误判成了整体几何坍塌，并造成不必要
的多次降学习率。

修正后保留实际更新 `0.1*tanh(raw/0.1)`、5% 连续饱和、体素跨度、非有限值和梯度
保护；原始残差改为：

- 绝对值 4.0 作为数值失控的应急上限；
- P99.9 超过 0.75 时立即判定为广泛尾部异常；
- 保留全像素尾部损失，并新增逐样本、逐轮最大残差损失，避免单点惩罚被约 20 万
  像素的均值稀释。

本次事件在新规则下归类为 `isolated_raw_outlier_false_positive`，不会再次消耗恢复
次数或继续降低学习率。续跑仍从完成全量评测的 step 7500 安全里程碑开始，失败分支
与旧阈值日志保持原样。
